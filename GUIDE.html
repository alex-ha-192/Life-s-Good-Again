Your 2023 LG can be made quiet and tile-based. Only the Home button needs root.

Kit v2, 25 Nov 2026. This replaces the earlier copy of the guide and zip. See what changed.

On stock firmware you can switch off Live Plus (ACR), the home-screen ads and promotions, block LG's ad and telemetry servers at your DNS, and run a fast tile launcher. Taking over the Home button and boot screen needs root, and whether a 2023 model can still be rooted depends on its exact firmware. Nothing in this kit touches the TV until you run it.

What changed in v2 use this version

The first version of the auto-renewal and DNS work had real bugs. If you already set any of it up, redo the steps marked below. Your pairing and settings backups carry over.

Developer Mode renewal fixed

The old renew opened the Developer Mode app without the extend flag and sent an undocumented call, so it probably never extended anything. It also ran once a month, so one night with the TV off meant expiry.

Now: lgtv_devmode.py sends the same extend as LG's Renew button. It checks every 3 hours, acts about weekly, retries until it works, and won't interrupt what you're watching. Redo: replace the old cron line or timer (steps).

Blocklist actually tightened

v1's "tightened" lists were unchanged. Now there are about 1,000 hosts plus catch-all rules for hosts LG adds later. A new opt-in strict tier blocks LG's whole service platform, and a DoH tier is meant for the TV only. Every list comes in 6 formats, built from one source.

Redo: re-add the base list to Pi-hole or AdGuard (steps).

Bypass closed, root trimmed

New: router rules so the TV can't go around your Pi-hole through public DNS, DNS-over-TLS, the public resolvers' DoH, or IPv6. Snippets for OpenWrt, MikroTik, pfSense and OPNsense, plus a checker, tools/dns_check.py.

The root section is now a short pointer to the Homebrew community's own checker.

Tiles Home v2 and one-step setup

The launcher is now a ring of five pages you turn with left and right, with icon and title rows and favourites on the yellow button. setup.py sets up the whole kit in one run.

Redo: reinstall the .ipk (how it works). Your old tile layout isn't carried over.

One-step setup new

On a stock TV, one script does everything below in order. It asks before each change, and --dry-run shows the whole plan without touching anything. Run it on the computer or Pi that will stay on:

python3 setup.py --dry-run                                  # see the plan
python3 setup.py --pihole http://192.168.1.2                 # or --adguard http://192.168.1.2:3000
python3 setup.py --pihole http://192.168.1.2 --tiers base,strict,doh   # strictest; strict + doh for the TV only
python3 setup.py status                                      # what's done, hours left, settings audit
python3 setup.py undo                                        # timer, DNS rules and TV settings put back

Run single steps with --only dns,schedule, or leave some out with --skip launcher. Everything the script adds to Pi-hole or AdGuard is tagged lgtv-privacy-kit, so undo removes exactly that. If you set up v1 by hand, re-running is safe: steps that are already done say so and move on.

If you'd rather do it by hand, or understand each part, the steps below are the same work done manually.

Setup by hand, in order

Steps 1 to 4 are safe and reversible. Each command that changes the TV shows its plan first.

  1. Find your model and firmware, and stop auto-updates for now

    On the TV: Settings, All Settings, Support, TV Information. Note the model (for a 43-inch 2023 4K it's usually a 43UR…) and the software version (03.xx.xx on webOS 23). Turn off Support, Software Update, Auto Update while you decide about root: an update can close the door for good. Or run step 3 then python3 lgtv_privacy.py info.

  2. Untick the consents on the TV

    Settings, All Settings, Support, Privacy & Terms, User Agreements: untick Viewing Information, Voice Information, Interest-Based Advertising, Content Recommendation, Live Plus. Then General, System, Additional Settings, Advertisement: Limit Ad Tracking on, Personalised Ads off, reset the Advertising ID. Run python3 lgtv_privacy.py manual for the full list.

  3. Pair the CLI and switch off the rest

    Allow phone control first: General, Devices, External Devices, enable TV On With Mobile / LG Connect Apps. Give the TV a fixed IP in your router.

    python3 lgtv_privacy.py pair --host 192.168.1.50   # accept the prompt on the TV
python3 lgtv_privacy.py audit                       # read-only report
python3 lgtv_privacy.py apply --dry-run             # see the exact changes
python3 lgtv_privacy.py apply                       # backs up, applies, reads back to verify
python3 lgtv_privacy.py restore                     # undo from the latest backup

    Groups can be applied separately: --profile privacy, --profile ads, --profile home. If a value doesn't stick, re-run with --press-enter; newer firmware sometimes wants the hidden alert confirmed. Keys your firmware doesn't have are reported as n/a and skipped.

  4. Add the DNS blocklist

    Pi-hole: Adlists, add lg-base.hosts (host the file on your LAN or paste it into a local list), then pihole -g. Then add each line of lg-base.pihole-regex.txt under Domains as a regex deny rule. These catch hosts LG adds later. AdGuard Home: Filters, Custom filtering rules, paste lg-base.adguard.txt. OpenWrt / dnsmasq / Unbound: use the .dnsmasq.conf or .unbound.conf file. Then hand out the filter as the only DNS server, and close the gaps in Airtight DNS.

    The base list leaves streaming apps, app installs and firmware alone. It does turn off LG Channels recommendation rows, Live Plus, and the LG ThinQ phone app's cloud link.

  5. Turn on Developer Mode

    Create a free account at webostv.developer.lge.com. On the TV install Developer Mode from the LG Content Store, sign in, switch Dev Mode Status on, let it reboot, then turn on Key Server. The session lasts about 1,000 hours (~42 days); if it lapses, dev apps are removed (reinstall takes a minute). Auto-renewal below keeps it alive for you.

  6. Install Tiles Home

    Easiest: install webOS Dev Manager on your PC, add the TV with the passphrase shown in the Developer Mode app, and drop in dist/io.github.lgprivacykit.tiles_1.0.0_all.ipk. With LG's CLI instead:

    npm install -g @webos-tools/cli
ares-setup-device                      # add the TV, passphrase from the Dev Mode app
ares-install -d tv dist/io.github.lgprivacykit.tiles_1.0.0_all.ipk
python3 lgtv_privacy.py launch

    For your real app list and icons in the launcher: python3 lgtv_privacy.py export-tiles, then python3 tools/build_ipk.py and reinstall. setup.py does both for you. The launcher also reads the list live, where the firmware allows it.

This is as far as stock firmware goes: the Home button keeps opening LG's home.

    Replacing the Home button, dropping the 1,000-hour timer, and on-TV blocking all need a rooted TV. See Root status. This kit doesn't cover rooting.

Keep Developer Mode alive automatically v2

Developer Mode lasts about 1,000 hours (about 41 days). When it lapses, LG removes sideloaded apps such as Tiles Home. Pressing Extend in the Developer Mode app resets the timer. lgtv_devmode.py does the same press for you over the pairing you already have, the way LG's own CLI does it (ares-launch com.palmdts.devmode -p '{"extend":true}'). It never touches firmware or settings.

1. Try it once

python3 lgtv_devmode.py renew --force    # the Developer Mode app flashes up, then your app comes back
python3 lgtv_devmode.py status           # last success, TV reachable?

2. Optional: exact hours left

With the session token, the helper asks LG's developer site how many hours are left. It then extends only when needed and confirms the reset worked. You can read the token through Developer Mode's own SSH, which is the same read-only access webOS Dev Manager uses. Turn on Key Server in the Developer Mode app first:

curl -o ~/.ssh/lgtv_webos http://192.168.1.50:9991/webos_rsa && chmod 600 ~/.ssh/lgtv_webos
python3 lgtv_devmode.py fetch-token --key ~/.ssh/lgtv_webos   # asks for the passphrase shown in the app
# or, if you already have it:  python3 lgtv_devmode.py set-token <token>

3. Put it on a timer

Run python3 lgtv_devmode.py schedule on the machine that will do this (your PC, Mac, or a Raspberry Pi that stays on). It prints the exact line for that system with your paths filled in. Add it yourself. The timer runs every 3 hours, but the helper only extends about once a week. With --polite it waits until nothing is playing, unless it's 2 or more days late. It keeps retrying while the TV is off.

# Linux / Raspberry Pi / macOS (crontab -e):
17 */3 * * * /usr/bin/python3 /path/to/kit/lgtv_devmode.py renew --polite >> ~/.config/lgtv-privacy/devmode.log 2>&1
# Linux, systemd user timer (units in tools/systemd/; edit the path first):
cp tools/systemd/lgtv-devmode-renew.* ~/.config/systemd/user/ && systemctl --user daemon-reload
systemctl --user enable --now lgtv-devmode-renew.timer && loginctl enable-linger "$USER"
# Windows (normal Command Prompt):
schtasks /Create /TN "LG Dev Mode extend" /SC HOURLY /MO 3 /F /TR "\"C:\Path\python.exe\" \"C:\Path\kit\lgtv_devmode.py\" renew --polite"
Upgrading from v1? Delete the old monthly line (0 3 1 * * … lgtv_privacy.py renew), or run sudo systemctl disable --now lgtv-devmode-renew.timer and remove the old units from /etc/systemd/system/. Then add the new timer above. The new units run as your user, so they can read your pairing in ~/.config/lgtv-privacy.
Exit codeMeans
0Extended, or not due yet.
75TV off or busy, will retry. Normal; systemd treats it as success.
2No success for 30 days. Open Developer Mode on the TV and press Extend. Shows as a failed run so monitoring can catch it.
1The TV refused, or the extend didn't take. Usually Developer Mode was signed out or removed.
The TV needs to be on, or in standby with TV On With Mobile and Quick Start+ on, when the helper runs. Retrying every 3 hours covers that. --web-fallback also tries LG's web reset while the TV is off, but there are reports that it answers "success" without resetting the TV's timer, so the helper only counts it if LG then reports about 1,000 hours. If Developer Mode ever does lapse, turn it on again and reinstall Tiles Home. Your layout is saved on the TV.

Airtight DNS: stop the TV going around your Pi-hole new

A blocklist only works if the TV actually asks your filter. Without root, this is as close to a complete block as you can get from the network side. Pick your tiers, close the four ways around them, then check.

1. Choose how much to block

TierBlocksBreaksScope
baseLG ads, ACR (Live Plus, Alphonso), beacons, recommendation feeds, every regional ad host, plus catch-allsLG Channels rows, sports cards, ThinQ cloudWhole network is fine
strictAll of LG's service platforms: lgtvsdp, nextlgsdp, lgappstv, lgtvcommon, lge.com, ThinQContent Store, app updates, firmware updates (and their security fixes), LG account, Search and voice, some home iconsTV only
dohThe well-known DNS-over-HTTPS services (Google, Cloudflare, Quad9, NextDNS, AdGuard and others)Nothing on the TV that I know ofTV only

Streaming apps (Netflix, YouTube, Prime, Disney+, Plex, Jellyfin) use their own domains and keep working on every tier. Scope to the TV only: in Pi-hole, Group Management, create a group "TV", add the TV under Clients, and assign the strict and doh lists only to that group. In AdGuard Home, run python3 tools/build_blocklists.py --client 192.168.1.50 and paste the *.adguard-tv-only.txt files. Their rules carry $client.

What is DoH? DNS-over-HTTPS. Normally a device looks up a name like lgsmartad.com by asking your DNS server in plain text, which is how your Pi-hole sees the request and blocks it. With DoH, the device sends the lookup encrypted, as ordinary web traffic, straight to a service like Google or Cloudflare. Your Pi-hole never sees it, so it can't block it. The doh tier stops the TV reaching those services by name, and the router rules below stop it reaching their addresses directly. It's a precaution: there's no public report of LG's own software using DoH, but an app on the TV could.

2. Close the four ways around it

BypassFix
A second public DNS server handed out by DHCP, or typed into the TVRouter DHCP: the Pi-hole as the only DNS server, secondary left empty. On the TV, set DNS by hand to the Pi-hole as well.
Hard-coded DNS (for example 8.8.8.8 on port 53)Router rule: the TV can't send port 53 to the internet.
Encrypted DNS: DoT/DoQ on port 853, DoH on 443Router rule: no 853, and no traffic at all to the big resolvers' IPs. The doh tier handles DoH by name.
IPv6: the router advertises its own IPv6 DNSMake the router forward to the Pi-hole, advertise the Pi-hole's IPv6 address, or turn IPv6 off for the TV.

Ready-to-paste, TV-only rules with undo lines are in router/: openwrt.sh, mikrotik.rsc, pfsense-opnsense.txt, and generic-router.txt for ISP routers with no firewall. For example, on OpenWrt:

uci add firewall rule
uci set firewall.@rule[-1].name='TV-no-DNS-bypass'
uci set firewall.@rule[-1].src='lan'
uci set firewall.@rule[-1].src_mac='TV_MAC'
uci set firewall.@rule[-1].dest='wan'
uci set firewall.@rule[-1].dest_port='53 853'
uci set firewall.@rule[-1].proto='tcp udp'
uci set firewall.@rule[-1].family='any'
uci set firewall.@rule[-1].target='REJECT'
uci commit firewall && service firewall restart

3. Check it

python3 tools/dns_check.py --dns 192.168.1.2

Read-only. It confirms that LG hosts come back blocked, that ordinary sites still resolve, and whether public DNS, DoT or IPv6 DNS can be reached around your filter. Run it from a machine the same router rules apply to. With TV-only rules, your PC will still show "bypass possible", which is expected.

The limit of DNS: it can't stop a connection to a hard-coded IP address. The fullest no-root option is a firewall allowlist: put the TV on its own guest or IoT network and let it reach only your streaming services. That takes the most upkeep. Blocking at the OS level needs root.

Root status: a pointer, not a how-to

Going lower than this kit goes needs root on webOS. That covers removing the 1,000-hour timer, taking over the Home button and boot screen, and blocking at the OS level. Whether a 2023 model can be rooted depends entirely on its exact firmware. Methods are patched over time, and LG firmware can't be downgraded, so once it's updated past a fix, the option is gone.

The webOS Homebrew community keeps the up-to-date answer. Check your model and firmware (python3 lgtv_privacy.py info prints both) at cani.rootmy.tv, and read about the Homebrew Channel there. This kit doesn't include or walk through any rooting method. The optional root/50-tiles-home boot hook only matters on a TV that's already rooted.

Holding back firmware updates to keep that option open also means going without LG's security fixes. If you do that, keep the TV off untrusted networks. The router rules above help either way.

Risks, plainly

  • Settings, DNS, Dev Mode: no bricking risk. All reversible: restore, remove the list, uninstall the app.
  • Warranty: changing settings and Dev Mode apps are things LG offers. Rooting isn't; LG can refuse service for software damage caused by it.
  • Bricking: nothing in the no-root kit can brick the TV. Root is outside this kit; see the community's own docs.
  • Updates: blocking them keeps root possible and also keeps known bugs open.

What the blocklist breaks

  • Base list: LG Channels rows and sports cards on LG's home, Live Plus, LG ThinQ remote features. Streaming apps work.
  • Firmware list: no more automatic updates.
  • Store list: installing and updating apps from LG's store, app icons in LG's home.
  • Strict tier: all of the above plus LG account, Search and voice. Scope it to the TV.
  • Router rules: nothing for streaming. An app with its own hard-coded DNS would fail to resolve rather than leak.

I left out entries in some community lists that block Google, Apple, Amazon and Philips Hue hosts, because they break apps for other devices on your network.

Not yet tested on a real TV

  • The CLI was run end to end (pair, audit, apply, verify, restore, export) against the included mock TV, not your set. Its write path is the alert-button method that bscpylgtv and Home Assistant users rely on; LG could restrict it on new firmware. The read-back after apply will tell you.
  • The settings keys come from community notes and vary by firmware; the CLI skips any your TV doesn't report.
  • The .ipk was built without LG's SDK and checked with dpkg-deb; it hasn't been installed on a TV. If Dev Manager rejects it, run ares-package launcher on the same folder.
  • v2 renewal: run end to end against the mock TV and a fake LG session site, covering due and not-due, polite deferral, return to the previous app, TV off, overdue, and web fallback. The extend call is the one LG's CLI and the Developer Mode app's Renew button use, but it hasn't been run on your set. renew --force followed by status will show whether it works on your TV.
  • setup.py: run end to end against the mock TV (pair, privacy, devmode, launcher build, router files, timer, maintain, guard, undo), plus fake Pi-hole v6 and AdGuard Home APIs (add, re-run, undo). It hasn't been run against your real Pi-hole or AdGuard yet; --dry-run first. Pi-hole v5 has no API for this, so on v5 use the manual step. Installing the launcher over Developer Mode SSH uses the same calls as LG's ares-install, but that path couldn't be tested here.
  • v2 DNS: the build script, regexes and dns_check.py were tested against a fake DNS server. The router snippets follow each platform's documented syntax but weren't run on real routers. Read them and fill in your IPs and MAC first.
  • The root boot hook follows the Homebrew Channel init.d convention but is untested.
